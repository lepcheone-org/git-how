Which GitHub account am I using?

One-page check before you push, and for Copilot chat. Three separate things are all called "my account". Check each one on its own.

Rule 1. The active login decides who pushes. The email in git config does not.
Rule 2. Pushing and Copilot chat are independent. Changing one never changes the other.
Rule 3. Open a new terminal? Check again. A background variable may switch you back.

1. Commit author

Who each commit is labelled as. A label only. It grants no access.

git config user.namegit config user.emailShows the name and email Git will stamp on your next commit. Run it inside the repo folder.
git log -1 --format="%an <%ae>"Who the latest commit says it is from.
git config --global --listEverything set for your whole Windows user.
Change for this repo only: run git config user.email "you@x.com" inside the repo (leave out --global).

2. Push login (terminal)

Who actually uploads when you run git push. This is the one that matters.

gh auth statusLists every login. The one marked Active account: true is used. Plain gh only shows help.
gh api user --jq .loginPrints just the active account name. The quickest check.
git remote -vShows where it will push. The URL is github.com/OWNER/REPO.
gh api repos/OWNER/REPO --jq .permissions"push": true means this account may upload there.
Switch active login: gh auth switch --user YOUR-PERSONAL-USERNAME

3. Copilot chat (VS Code)

Which account powers the chat panel. Has nothing to do with pushing.

Accounts icon (person), bottom-leftLists every account VS Code is signed in to.
Click an account > Manage Trusted ExtensionsIf GitHub Copilot Chat is ticked for that account, chat uses it.
Copilot icon, bottom-right status barShows Copilot status and usage for the signed-in account.
Change it: Accounts icon > the account > Sign Out, then sign in to the one you want when Copilot asks. Menu wording can vary a little by VS Code version.

Before every push: 5-step check

Takes 20 seconds. Run in the VS Code terminal, inside the project folder.

  1. git statusRight folder and branch? Anything unexpected staged?
  2. git remote -vIs the URL the right org and repo?
  3. gh api user --jq .loginDoes it print your personal username?
  4. gh api repos/OWNER/REPO --jq .permissionsIs "push": true?
  5. git push -u origin mainOnly now. -u is needed just the first time for a branch.

Write down your own accounts

Fill these in for yourself. The accounts can all be different people or roles.

AccountUse it for
YOUR-PERSONAL-USERNAME PUSHPersonal. Use for pushes to your own repos or org. Commits use your name and the email on this account.
YOUR-COPILOT-ACCOUNT CHATThe account you sign in with for Copilot chat in VS Code. It does not have to be the one you push with.
YOUR-WORK-ACCOUNT WORKWork account. Keep it away from personal projects. Watch for a GH_TOKEN that points at it.
Add / remove a login: gh auth login  |  gh auth logout --user NAME. When logging in, check the browser avatar says the account you want before you click Authorize.

The GH_TOKEN trap (this caught us once)

A Windows variable called GH_TOKEN overrides every stored login. If it is set, you push as whoever owns that token, whatever else you switch.

How to spot itIn gh auth status, the active account says (GH_TOKEN) instead of (keyring).
Where is it set? (prints True/False only)foreach ($s in 'Process','User','Machine') { "{0}: {1}" -f $s, ($null -ne [Environment]::GetEnvironmentVariable('GH_TOKEN',$s)) }
Fix for this terminal onlyRemove-Item Env:GH_TOKENComes back in every new terminal. Removing it for good (Windows "Environment Variables") may break other tools, so only do it if you know nothing needs it.
